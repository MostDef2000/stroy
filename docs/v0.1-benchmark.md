## Known Limitations / Next Priorities

- **Generation conditioning**: Currently based on prompt+seed only; geometry/style conditioning descoped from the first workflow (see #13 close-out) — top v0.2 priority.
- **Blender Rendering**: `render.blender` executes as a fake stub on the VPS worker (no Blender binary present; rendering is a home-workstation capability).
- **Replacement pixels**: `image.edit` runs as a fake executor on `stroy-vps-1` (the 2 s success in step 11 proves orchestration only). Real pixel replacement awaits the box worker advertising `image_edit` with the kontext model (`flux1-dev-kontext` already downloaded).
  - *Resolved 2026-09-26 (v0.2, #57–#60)*: real FLUX.1 Kontext replacement is live on the GPU box — job `e43e1a67`, 55 s, VRAM peak 10916 MiB, provenance `image-edit-kontext-v0` + `comfyui/0.35.0`; VPS no longer advertises `image_edit` (fake can no longer intercept replacements). **Semantic caveat from vision review**: with a whole-room photo as the reference and a generic instruction, the result collapsed toward the reference image instead of swapping the single target entity. Object-level replacement needs the conditioning work (object-level reference crops / affected-region masking / structured prompt conditioning) — first v0.2 priority.
- **UI walkthrough**: steps 3–5 exercised via API (minimal valid scene; prod `scene_revisions` were zero before this run). Full golden-room geometry load/correct + calibrated-camera walkthrough in the UI remains — first polish item.
- **Ollama Context**: Ollama on the PC uses context wrappers (qwen3-vl-16k) because default context is too large; `think:false` requires an ollama upgrade.
- **Diagnostic API ergonomics**: `GeometryDiagnosticRequest` takes `edge_threshold` as int 1–255 (not 0–1) and `tolerance_px` 0–16 — document in the API reference.
- **System Updates**: 64 apt packages on the box await root updates.
